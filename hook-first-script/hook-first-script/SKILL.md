# Hook-First Video Script

Write a script people watch to the end. Two standards drive everything: give viewers a reason to keep watching within the first 15 seconds, and leave them a reason to wonder "what's next?" throughout the video.

## Language
Reply and write all deliverables in the user's language (Korean, English, Japanese, …). Ask once if unclear. If the video's language differs from the chat language (e.g. the user chats in Korean but wants an English video), write the script in the video's language and the notes in the chat language.

Worked example: `references/example_en.md` ("How to fall asleep faster", 3–5 min).

## 0. Ask first (if you don't know, ask before writing)
1. The topic, plus one sentence on what the viewer walks away with
2. The audience: who they are and how much they already know about the topic
3. Length: 3–5 min / 8–12 min / 15–20 min. Size the script by speaking pace (rules of thumb; adjust to the narrator):
   - Korean: about 280–320 characters per minute
   - English: about 140–160 words per minute
   - Japanese: about 300 characters per minute
4. Tone: talking to a friend / calm explainer / light humor (pick one). If the channel already has videos, ask for one existing script and match its tone.
   - Register also differs by language: Korean polite speech (haeyo-che) vs. casual speech (banmal); Japanese desu/masu form vs. casual form; English has no honorific forms, so set the register with word choice (casual vs. professional). Confirm which one the channel uses.
5. Sources and facts the user can provide. If there are none, don't invent any: tell the user you will only use verified facts and list the rest for checking.

## 1. Script structure
| Section | What it does | Target length |
|---|---|---|
| Hook | Grab attention with a problem, a question, a twist, or a concrete number | Within 15 s |
| Promise | One sentence: "In this video, you'll learn ○○." No exaggeration | Within 10 s |
| Body | 3–5 parts. Each part: claim → evidence or example → tease of the next part | 70–80% of the total |
| Recap | Three-line summary of the key points. No new information | 20–30 s |
| Next step | One subscribe ask + one sentence linking to the next video | Within 15 s |

## 2. Hook patterns (use only the one that fits this video)
- **Problem**: "If you do ○○, this happens."
- **Surprising fact**: one concrete fact that runs against common belief
- **Number and result**: "In ○○ days, ○○ changed" (only when it's true)
- **Question**: a question viewers answer in their heads. Avoid yes/no questions.
- **Scene**: start in the middle of the story and explain later

Always give 3 hook options and recommend the strongest one. No clickbait exaggeration (never promise something the video doesn't deliver).

## 3. Retention devices
- End every part with an open loop. Example: "But here the opposite result shows up. Why? That's the next part."
- Every 3–4 minutes, add a refresh point: a scene change, a question, an example, or a twist.
- When an explanation gets long, show the example first, then the principle.
- Don't start consecutive sentences the same way ("So…", "And…", or the equivalent connectors in Korean and Japanese).

## 4. Spoken-style rules
- Each sentence should be readable aloud in one breath. Rough guide: Korean about 40 characters, English about 15–20 words, Japanese about 40 characters.
- Avoid written-only phrasing. English: "regarding", "it can be said that", "furthermore". Korean and Japanese have the same trap: stiff report-style endings and formal connectors that nobody says out loud.
- Write numbers the way they are spoken, and match the TTS or narrator. Example: "2026" → "twenty twenty-six" in English; in Korean and Japanese, spell the year as it is read aloud in that language if the TTS misreads digits.
- Explain a technical term once, the first time it appears.

## 5. Output format
```
[3 title drafts]
[3 hook options + 1 recommended]
[Script]
  00:00 Hook …
  00:15 Promise …
  Part 1 …  (shot note: one line on what's on screen)
  …
[Recap & next step]
[Fact-check list]  ← sentences that need verification
```

## 6. Don't
- Present unverified numbers, quotes, or effects as fact
- Give definitive medical, legal, or investment advice (separate reporting facts from personal judgment)
- Promise anything in the title or hook that the video doesn't deliver

## 7. Checklist
- [ ] Within 15 seconds, it's clear what the viewer gets
- [ ] Every part ends with an open loop
- [ ] The recap contains no new information
- [ ] Sentences that need fact-checking are on the list
- [ ] Reading it aloud, nothing trips you up
